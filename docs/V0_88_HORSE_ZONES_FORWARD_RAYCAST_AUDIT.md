## Horse Everywhere
User clarifies **two independent restriction types**:
1. **Cannot summon** horse via H or LB+RB in restricted zones, but already active horses are not necessarily removed.
2. **Explicitly horse-banned volumes**, where a ridden horse vanishes when crossing their boundary, and cannot be summoned within them.
Do NOT conflate these. The V0.87 log has `serverSpawn=2 duringRequested=1` and many `LB+RB` presses with `serverDelta=0`. It also exhibits `camera pose source = HORSE` then `FOOT`. Old `HorseFeature::Telemetry.validated` could remain true indefinitely after **any** observed horse, so V0.87 `liveHorse=1` must not be used to assert present ownership. A key chord can request a voluntary dismount, too; `serverDelta=0` alone cannot prove an area restriction.

- **Config default ON** everywhere: store Reset Defaults, fallback when INI value absent, Snapshot default, runtime atomic default and distributed INI `[Features] HorseEverywhere=1`. `ConfigRevision=2127`: migrate the pre-2127 default-OFF to ON exactly once, then honor user's explicit OFF from new config. ThirdPerson=0 and ALL other gameplay defaults unchanged.
- UI says “Horse Everywhere (research, default ON)” and explicitly warns **NOT YET FUNCTIONAL** in either type of restricted zone.
- Observational native callback freshness: add `HorseFeature::Telemetry.horseCallbackFresh`, `lastHorseNativeTick`, `horseGeneration`. Detect actual native callback recency and horse identity changes during `HorseCharacter` hooks. *Do not cache/dereference stale pointers.*
- Better summon input diagnostic: when real H or LB+RB input occurs, snapshot REAL CURRENT mounted TPS view (not the old permanently true `validated` flag), recent horse pose and callback count, owner generation and approximate player world coordinates. After 1.8 s log delta of server calls and native callbacks and current mounted camera. These are **correlations, not automatic proof** of restriction.
- Passive `HORSE -> FOOT` camera-source transitions log player location, age of last native horse pose, and time since last real summon/dismount key. If no recent key was pressed, a forced-removal volume is more plausible; if a key was pressed, it may just be voluntary dismount. No forced respawn/retention, no bypass of mission volumes or player safety gating. This keeps the game stable.
- **Important:** Horse Everywhere ON is a requested default and a *diagnostic opt-in for future bypass*; the two actual zone checks are NOT overridden in V0.88. User's new geographic distinction is the basis for next native/BP gate audit.
