## What V0.89 actually does
- Exact retail EXE native methods `AMayhemPlayerCharacter::IsInHorseRegion` RVA 0x675E40 and `IsInHorseDesummonRegion` RVA 0x675D20, MinHook validated by 12 byte signatures.
- Every getter invokes the genuine game function FIRST. The answer is altered **only when** all conditions hold: HorseEverywhere enabled (default ON since V0.88, user requested), actor identity matches a recently observed **validated local player movement owner**, and a real H or LB+RB input rising edge was observed within 1,600 ms. On this narrow input window, `IsInHorseRegion` false -> true and `IsInHorseDesummonRegion` true -> false. No global volumes changed. Outside the window return original result. This is an **unvalidated test**: it may make local summons possible in some forbidden areas but has not yet been observed.
- BANNED area type #2 (horse forcibly removed on entering): the 1600ms window **does not** persist to prevent that removal. Do NOT claim Horse Everywhere works in those zones. A broad override could break mission boundaries, so do not apply until observed getter outputs and reason for removal are known.
- New overlay counters regionQueries / regionOverrides and desummonQueries / desummonOverrides. Toggle OFF is immediate fallback, no restart necessary, rollback archive V0.88 remains.
- When native server-spawn event precedes `AREA INPUT` by <250ms, `serverJustBeforeInput=1`; subsequent result prints `correlatedServer=1` rather than incorrectly claiming failure. A separate horse generation change still measures actual spawned actor.
- Camera Forward: **passively** count when `GetPlayerLookInput` receives exact freshly detected horse pawn identity, even if player-only eligibility filter would reject it. No changes whatsoever to getter return values or raycast and no camera orbit/aim mode 1 edits. At the end log `TPS V0.89 CAMERA FORWARD: horseActorGetPlayerLookInputCalls`.
