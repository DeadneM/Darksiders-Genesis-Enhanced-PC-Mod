# V1.27: Mounted mouse pose continuity and native character-facing audit

Date 2026-10-14 · **debug** only · experimental candidate. Base V1.26 user feedback: **mouse camera works well**; 2 of 3 cinematics temporarily returned to native camera; remaining cinematic missed. Two newly reported gameplay issues: **mounted Strife shots do not land along camera forward**, and **at rest / during transitions the character may face the screen or sideways**, revealing a player-facing versus camera-heading mismatch. No V1.26 log attached to this feedback, therefore no new per-event counter values can be asserted.

## Actual source root causes and constraints
- `HookPlayerLookInput` (0x671A40) changes the native local-player look vector to TPS camera heading **only while shooting**. That getter is not the game's proven mounted projectile direction. Historical V0.89 verified **0 actual horse-actor GetPlayerLookInput calls**. `HookPlayerLookRotation` (0x671B00) was called rarely in historical user tests and is not confirmed as the authority for idle/animation body yaw. Never conflate corrected getter output with actual bullet trace or mesh orientation.
- Mounted camera view `CameraTraceFeature::HookView` originally uses `RuntimeSettings::tpsAimActive` to preserve recent verified horse pose during firing, but that atomic is written ONLY by native-pad `FilterNativeXInput` firing. Mouse firing in V1.24+ was never propagated to the mounted view's pose hold.
- `bOrientRotationToMovement` read from local movement component at validated native offset `+0x240` bit `0x10`; old experiments only forcing movement facing were rejected (V0.61/V0.66/V0.71). Do not repeat that intervention without finding the actual authoritative character/animation rotation path.
- External research clue (not imported or verified for our exact EXE): [Klassik 3rd person cam](https://www.nexusmods.com/darksidersgenesis/mods/2) advertises bullet raycasts aligned to the camera through native object/rotation code. Its Steam build id #49453 must not be treated as exact-match offsets/signatures to our executable SHA-256 `9f4702024df5eea1d51df7745b0ad1ea95b97009982f73ddc1218c53dff33d54`. No copied CE hooks.

## V1.27 code
1. Publish **separate** focused physical mouse-fire state from `UpdateOrbitInput` (`tpsMouseFireHeld/tpsMouseFireTick`), without interfering with RawInput, `WM_MOUSEMOVE`, cursor recapture, WndProc remapping or native XInput firing.
2. `CameraTraceFeature::HookView` can hold a previous **fresh verified horse** pose during physical mouse firing for mounted TPS, just like its already established native-pad pose stabilization; no stale horse UObject dereference. This is a camera pose continuity adjustment, **NOT a mounted bullet-raycast redirection**.
3. Read-only `TPS V1.27 FACING_AUDIT` logs of native local actor / live horse pose yaw relative to applied TPS camera yaw (with accurate label **HORSE_POSE** != rider mesh); counts for >75-degree differences, summarized in `FACING_CAMERA totals`.
4. Read-only `TPS V1.27 FACING_NATIVE` logs of the observed movement-component bOrientRotationToMovement flag and native root yaw versus camera yaw, sampled only within the existing live-local movement callback. No flag writes added.
5. Read-only mounted mouse shooting `MOUNTED_MOUSE_LOOK_GETTER` and `MOUNTED_MOUSE_LOOK_ROTATION` counts and return caller RVAs **only if these functions were actually invoked**. A zero horse getter count will reinforce that shot trajectory bypasses this getter; a nonzero count is **not proof** of projectile steering. No new native detours or projectile spawning hacks.
6. Keep V1.26 persistent RawInput re-registration, native firing, mounted Vanilla Aim option (mode 1), R3 temporary view, all horse/Combat/HUD/synergy/startup functions untouched. No new Hide Reticle.

## Outstanding functionality
- To fix **real camera-forward mounted bullets**, require exact retail EXE bytes / native raycast callsite with guard signatures. Preserve muzzle origin, collision and weapon lifetime. Do not force actor yaw or reuse rejected virtual Ctrl input.
- To fix **idle-facing/player pose**, identify root rotation authority (movement `PhysicsRotation`, controller facing, character/anim logic), then make an opt-in camera-facing mode with smooth transitions and gamepad + mouse parity without spoiling strafe/dodge. This V1.27 is only evidence collection.
- For **third missed cinematic**, a camera-shape heuristic will not recognize in-place/nearby cutscenes. Native Sequencer/dialogue/camera owner must be identified; no heuristic timeout changes in V1.27.
- Warnings still not skipped. Wrath/Ultimate gain multipliers still unverified; existing Synergy x2 previously validated.

## User game test
Keep two guns at rest facing an easily visible environment cue, orbit camera past 180 degrees (without firing) and capture visual body rotation; then fire a few mouse shots at the same target with Strife mounted and on foot. Try left and right click separately, alternate between on-foot/horse with no camera reset, and trigger one cinematic if nearby. Send **whole log**. Focus on `FACING_AUDIT`, `FACING_NATIVE`, `MOUNTED_MOUSE_LOOK_GETTER`, `FACING_CAMERA totals`; note where shots land and when body faces backward. The goal is to identify actual native shot/facing callsites for a later functional correction; no claim that V1.27 fixes visual aim accuracy.
